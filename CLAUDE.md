# Harness Engineering 101 (and LLMs 101)

Two mdBooks in one repo. The root is *Harness Engineering 101*: 16 chapters
plus appendices with a runnable toy harness in plain Python. `llms-101/` is
its sequel, *LLMs 101: Inside the Brain*: 20 chapters plus appendices with a
toy GPT (NumPy forward pass on real GPT-2 weights, PyTorch training). Both
render to static HTML and are served on the blog.

## Voice and goal — read before editing any prose

The goal is to deliver the *intuition* behind harness engineering, with no
buzzwords, and help people navigate what is otherwise a confusing mess. When
writing or editing chapter prose, hold to these:

- Plain, simple English. No jargon, no hype, no buzzword tours. Spell things
  out.
- Minto pyramid: lead with the answer/conclusion, then the support beneath it.
- Conversational tone, written as the author's (Isuru's) first-hand
  experience — first person, "I watched this show up one patch at a time."
- The toy harness is the hero/spine of the series; One Code is the
  production-scale companion, cited as evidence and for advanced examples only,
  never promoted.
- Every chapter has the same shape: the failure, the minimal patch, what the
  patch costs. Applies to both books.

The same rules apply to `llms-101/`, with these additions:

- The organising sentence is "an LLM is one function: tokens in, a probability
  for every next token out; everything else is how it is built, taught, or
  run." Every term lands on one of those three shelves.
- Each chapter opens with a question the harness book left open (the
  "body-book question" column in `llms-101/src/README.md`) and answers it.
- Voice: first person from eight years in AI (classical ML since 2018, thousands
  of models trained, a few hundred LLM fine-tunes for the EnSiTa and
  Confident-but-Wrong papers,
  code-retrieval embedding models). Papers are cited as evidence, never
  promoted. Cross-link the harness book by absolute URL
  (`https://isuruwijesiri.com/harness-engineering-101/<page>.html`).
- Every number in the prose comes from a real run of the code in
  `llms-101/src/gpt/`. Do not invent outputs; run the script and paste.

## Commands

```bash
mdbook serve --open          # live preview at http://localhost:3000
mdbook build                 # static site into ./book
./scripts/sync-to-blog.sh    # build + copy book/ into the blog repo (see Publishing)
cd src/diagrams && python3 gen_all.py   # regenerate the quantitative PNGs

# LLMs 101 (run from llms-101/)
mdbook serve --open                     # preview the second book
./scripts/sync-to-blog.sh               # build + copy into the blog repo's llms-101/
cd src/gpt && python3 make_corpus.py    # rebuild corpus.txt from the harness chapters
cd src/gpt && python3 download_gpt2.py  # fetch GPT-2 weights + tokenizer into llms-101/models/ (~550 MB, gitignored)
cd src/gpt && python3 v3_forward.py     # NumPy GPT-2 forward pass (chapter 7)
cd src/gpt && python3 v4_train.py       # train the toy, writes loss.csv (chapter 8, ~5 min)
cd src/gpt && python3 gpt.py train      # the epilogue's single-file toy (~3 min)
cd src/diagrams && python3 gen_all.py   # loss curve + attention heatmap PNGs (needs gpt2/ and loss.csv)
```

## Layout

- `src/*.md` — chapters and appendices (the book). `src/SUMMARY.md` is the TOC.
- `src/harness/` — the runnable toy harness, one file per stage.
- `src/diagrams/` — diagram generators and their PNGs.
- `book.toml` — mdBook config. `scripts/sync-to-blog.sh` — the publish script.
- `llms-101/` — the second book, same layout: `src/*.md`, `src/gpt/` (toy GPT,
  one file per stage plus `gpt.py`), `src/diagrams/`, own `book.toml` and
  `scripts/sync-to-blog.sh`. `src/gpt/corpus.txt` is the harness book's text,
  generated by `make_corpus.py`; regenerate it after editing harness chapters.

## Publishing

This repo is the source; the deployed book lives in the blog repo
(`/Users/isuruWij/me/IsuruMaduranga.github.io`, Cloudflare Pages →
isuruwijesiri.com/harness-engineering-101/), which serves committed static
HTML. **Editing `src/` does not update the live site on its own.** After any
content change, publish both repos:

1. `./scripts/sync-to-blog.sh` — rebuilds the book and copies it into the blog.
2. Commit and push this repo (`main`).
3. In the blog repo, commit `harness-engineering-101/` and push — that push is
   what goes live via Cloudflare.

For `llms-101/` the flow is the same with `llms-101/scripts/sync-to-blog.sh`,
which lands in the blog repo's `llms-101/` (isuruwijesiri.com/llms-101/). The
blog's jekyll-minifier exclude list needs `llms-101/*` added, alongside the
existing `harness-engineering-101/*` entry, before the first publish.

The `v1.0.0` git tag tracks the current published edition; move it to the new
HEAD when you publish an edit that should be part of v1.

## Conventions

- Links from the book to code point to GitHub, not relative paths — the site
  serves raw `.py` as downloads. Inline diagram PNGs stay relative so they embed.
- Link to the intro page as `index.html` (mdBook builds `README.md` as
  `index.html`; a `README.md` link 404s). `SUMMARY.md` keeps `README.md`.
- `llms-101` code links point at
  `https://github.com/IsuruMaduranga/harness-engineering-101/blob/main/llms-101/src/gpt/<file>`.
  If the book moves to its own repo, one `sed` over `llms-101/src/*.md` fixes
  them.
